# API 凭据使用平台安全能力加密保存

VoxFlow 的 API Key 不再写入普通 `SharedPreferences`。Windows 使用当前用户作用域的
DPAPI 加密后保存为 HKCU 下的二进制值；Android 使用不可导出的 Android Keystore
AES-GCM 密钥加密，并仅把版本化密文保存在应用私有偏好中。Flutter 通过固定
MethodChannel 契约读写凭据，平台错误只返回稳定错误码，不包含密钥、密文或原生错误
正文。

平台安全存储加密的值是版本化凭据包，包含 API Key 和保存时规范化后的 API Root；
普通偏好仍保存 API Root 以供界面编辑。启动时只有安全包内 Root 与普通偏好中的有效
Root 一致，Flutter 才会向运行状态暴露 Key。Root 缺失、无效或不匹配时必须持久标记
恢复状态、隐藏 Key 且禁止自动联网，直到用户重新保存一组完整凭据。

启动时若发现旧版 `settings.api_key` 明文，或安全存储中只有旧格式的原始 Key，必须先
确认同时存在有效 API Root，再写入并回读新的绑定凭据包，最后删除明文。安全值与旧版
明文冲突时以安全值为准；缺少配套 Root 不视为可安全迁移，此时必须先验证删除旧明文，
再进入恢复状态并要求用户重新输入完整凭据。Android 禁用应用数据备份，并在新旧备份
规则中排除全部数据域，避免恢复不可解密密文、历史明文、诊断日志或受管音频。

API Key 与 API Root 的界面配置跨越平台安全存储和普通偏好，保存时使用持久的未完成
事务标记。只要更新未被完整确认，或两处 Root 不能相互验证，启动过程就保持
fail-closed，不读取密钥也不自动联网，避免把旧供应商密钥发送到错误的 API Root。

该决定保护静态存储中的凭据，但不宣称防御已控制当前 Windows 用户、已 root 的 Android
设备、调试器或进程注入；网络请求发起时 API Key 仍会短暂存在于应用进程内存中。
